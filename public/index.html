AxiomSQL Academic Research Formulation & Novelty Factors

Abstract

Large Language Models (LLMs) exhibit notable capabilities in converting natural-language specifications into SQL queries. However, their reliability decreases on complex schemas with multi-table joins, nested groupings, and domain constraints. We propose AxiomSQL, an execution-driven framework formulating Text-to-SQL as an end-to-end differentiable computational graph optimized via TextGrad with an Adaptive Stopping Controller.

Novelty Growth Factors (G-Factors)

  1. Two-Stage Differentiable Computational Graph: Decouples high-level relational query planning (V_plan) from dialect-compliant SQL synthesis (V_sql). Runtime execution errors backpropagate upstream from concrete syntax to high-level relational topology.
  2. EXPLAIN-Grounded Plan-Cost Optimization (L_cost): Incorporates database query engine execution plans (EXPLAIN QUERY PLAN) into the objective function, penalizing unindexed table scans (SCAN TABLE) and temporary B-Trees to yield performant, index-friendly queries.
  3. Empty-Set Trap Cardinality Regularization (L_card): Identifies queries that run without syntax errors but return zero rows on populated databases due to over-constrained WHERE predicates.
  4. Adaptive Stopping Controller (Dynamic Hyperparameter K): Eliminates the "Over-Iteration Degradation" phenomenon where fixed iteration counts corrupt already-correct queries. Evaluates Execution-Gated Early Exit (EGEE), Textual Gradient Convergence (TGC), and Pareto Cost Utility (PUS).
  5. Anti-Oscillation Momentum Memory Buffer: Penalizes cyclic exploration of previously rejected SQL hypotheses.

Mathematical Formulation

$$\mathcal{G} = (V_{\text{nl}}, V_{\text{schema}}, V_{\text{plan}}, V_{\text{sql}})$$
$$\vec{\mathcal{L}}_{\text{exec}} = \langle \mathcal{L}_{\text{syntax}}, \mathcal{L}_{\text{schema}}, \mathcal{L}_{\text{cardinality}}, \mathcal{L}_{\text{semantic}}, \mathcal{L}_{\text{cost}}, \mathcal{L}_{\text{ast}} \rangle$$
$$\nabla_{V_{\text{sql}}} \mathcal{L}_{\text{exec}} = \text{CriticLLM}(V_{\text{sql}}, \mathcal{L}_{\text{exec}})$$
$$\nabla_{V_{\text{plan}}} \mathcal{L}_{\text{exec}} = \text{CriticLLM}(V_{\text{plan}}, V_{\text{sql}}, \nabla_{V_{\text{sql}}} \mathcal{L}_{\text{exec}})$$
$$\pi_{\text{exit}}(s_t) = \mathbb{I}\left( \text{Success}(Q_t) \land \|\nabla_{\text{text}}^{(t)}\| \le \epsilon \lor U(t) \ge \tau \right)$$
